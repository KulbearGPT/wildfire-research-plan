Lesson task · Find the extra changed variable

Would you trust this comparison?

For each case, choose the repair that lets us test the schedule. The goal is to change one intended factor while matching the rest.

Three short reasoning exercises

1 · ERM gets 1,000 updates. X22 gets 3,000.

Reason through the question and every option

How to reason: The schedule comparison currently changes both schedule and update count. Extra optimization is an alternative explanation for any score difference, so establish an equal continuation budget before interpreting scores.

  • Report only the higher AP — not the answer. Reporting only the winner removes the comparator without removing the confound. You still do not know whether the result came from the schedule or the extra updates.
  • Start both from B3 for 3,000 updates — correct. Independent starts from the same B3 and 3,000 updates per branch remove the stated budget mismatch. Preserve the other settings so the intended contrast remains the schedule.
  • Divide each AP by its update count — not the answer. AP is not proportional to update count. Dividing by updates produces a different quantity and cannot reconstruct how the shorter run would have performed after matched training.

Take away: Compare at the predeclared budget. If unequal runs already exist, retain them as unmatched evidence rather than correcting their AP by arithmetic.

2 · X22 starts from ERM’s final checkpoint.

Reason through the question and every option

How to reason: Initialization includes what the checkpoint has already learned. Starting X22 from ERM’s final weights gives it the ERM stage plus its own continuation; starting from B3 gives it only the intended continuation.

  • Use the same random seed only — not the answer. A random seed controls parts of the stochastic computation, not the learned weights loaded at initialization. Matching seeds cannot remove ERM’s prior updates.
  • Rename the checkpoint to B3 — not the answer. A filename is a label, not the model state. Renaming the file does not alter its weights or erase its training history.
  • Restart X22 independently from the actual B3 weights — correct. Loading the actual same B3 weights independently restores the intended common starting point. Verify checkpoint identity and use the declared fresh optimizer setup for both branches.

Take away: Verify bytes and provenance, not names. Continuing an interrupted run with optimizer state is a different operation from starting a fresh branch.

3 · X22 uses best validation AP; ERM uses final step.

Reason through the question and every option

How to reason: Checkpoint selection is part of the method being evaluated. “Best validation” and “final step” can choose different weights from the same run, creating a second changed factor beside the schedule.

  • Use the predeclared final-step rule for both — correct. Using the predeclared final continuation step for both branches removes the selection-rule mismatch. Keep the foundation’s earlier selection stage distinct from continuation selection.
  • Choose whichever checkpoint makes X22 look best — not the answer. Choosing whichever rule makes X22 look best adapts the experiment to the observed outcome. That prevents a clean schedule-only interpretation.
  • Use each model’s best test score — not the answer. Using test scores to choose weights turns the test set into selection data. The resulting maximum is not an independent test assessment.

Take away: Freeze selection before inspecting outcomes. Matching selection rules is necessary, but does not by itself guarantee matched data, budgets or initialization.

Done when: you can name each confound: budget, initialization history and checkpoint selection.

Exit question

X22 beats frozen B3, but loses to ERM. What did we learn?

Answer aloud or in your report before opening the explanation.

Check your reasoning

Work through the comparisons: call frozen B3 A, ERM B and X22 C. The question tells us C > A and C < B, hence B > C > A. Both continuations improve on the frozen foundation, but ordinary continuation performs better than X22 in this run.

  • “The schedule helped because X22 beats B3” is unsupported. C − A includes the whole continuation recipe. The relevant schedule comparison is C − B, which is negative here.
  • “Additional training did not help” also contradicts the comparison. Both B − A and C − A are positive. A negative schedule comparison does not imply a negative total change.
  • “Cosine never works” goes beyond the evidence. This result concerns the stated run and metric, not every seed, scenario or training setting.
  • A supported conclusion: under the matched contract, X22 improves on frozen B3 but underperforms ERM on the reported metric in this run; it does not establish a positive schedule contribution.

Check before concluding: both branches must start independently from the same B3, with matched budgets and evaluation. Starting X22 from ERM’s final checkpoint invalidates this intended comparison.

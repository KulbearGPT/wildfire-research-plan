Separate queueing, execution failure and missing output

  1. Pending: keep the existing job ID and inspect its queue reason. Work on the teaching report while waiting; do not submit duplicates.
  2. Setup or smoke failed: preserve the first error, job state, log path and configuration. Use project recovery or the official tutorial's troubleshooting chapter, according to your protocol.
  3. Process completed but checkpoint or metrics missing: inspect actual update count and the first missing artifact. Do not mark the practical complete or rerun all stages blindly.

When asking for help, provide protocol, intended step, source revision, job ID, expected artifact, actual artifact/log location and the first error. Do not include credentials.

Separate a disappointing result from an invalid comparison

If a metric is missing, check its schema and scenario key; leave an unavailable value missing. If sample identities, starting weights or checkpoint selection differ, repair the comparison before attribution.

If the contract is matched and the method does not improve, report the valid outcome. Do not extend the budget, change the main metric or try a weaker control to manufacture success.

Hand over either a traceable result, a precisely described execution blocker, or a preparation-only plan. Each must say what is complete and what remains. Use the report checklist.

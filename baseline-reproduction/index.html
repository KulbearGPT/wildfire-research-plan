01 · Framing

Why reproduce before inventing?

A new model is meaningful only after the existing one is understood under the same data split and evaluation rules.

  1. Make the comparison fair

    Freeze the dataset, folds, inputs, target, metric, and budget.

  2. Expose assumptions

    Reveal disagreements among configs, runtime overrides, and preprocessing.

  3. Separate science from plumbing

    Do not confuse model behavior with import, loader, or parser failures.

  4. Build auditable evidence

    Keep raw metrics, hashes, and independent checks.

Beginner rule: reproduce the smallest official baseline before changing the architecture.
02 · Vocabulary

Four terms to understand before the workflow

Four terms define what is being reproduced and compared.

What is a baseline?

The existing method that anchors comparison. Here it is official Res18-U-Net under the paper's folds.

What is a fold?

One predefined train/validation/test assignment. Twelve official folds expose sensitivity to year selection.

What is a checkpoint?

Saved learned weights. A released checkpoint can be tested without repeating training.

What is average precision?

AP summarizes precision–recall across thresholds. It suits rare fire pixels but does not describe one fixed threshold.

Training reproduction asks whether we can learn a comparable checkpoint. Released-weight reproduction asks whether the authors' checkpoint produces the expected metrics here. We did both for Fold 2, then tested all twelve released weights.

04 · Experiment design

Freeze the question before touching the code

A scientific contract separates allowed compatibility work from scientific choices that must remain fixed.

Frozen scientific choices

  • model class and forward computation;
  • official fold and year assignment;
  • input channels, crop, batch, precision, and seed;
  • loss, optimizer, learning rate, and test metrics;
  • released weight identity for test-only evaluation.

Allowed compatibility work

  • isolate a pinned Python environment;
  • remove imports for files missing from the official commit;
  • lower Windows data-loader workers after a no-training smoke;
  • parse platform-specific Lightning output;
  • collect official outputs and record provenance.
Scientific contract: it lets us classify a changed number as scientific (model/data/protocol) or operational (environment/loader/parser).
05 · Implementation lineage

Reuse official code, then wrap it with evidence

We kept the official scientific path and added control and verification around it.

Official layer
Res18-U-Net, data, loss, checkpoint loading, and test metrics.
Control layer
Frozen commands, one process lineage, no automatic retry, and atomic outputs.
Verification layer
Separate code re-reads raw logs, weights, inventories, timing, and metrics before PASS.
Engineering compatibility The runtime patch deleted seven unused eager architecture exports for files absent from the pinned commit. Required training imports remained; it did not modify the model, loss, optimizer, data, or metrics.

Correct code on the wrong files or folds is still a wrong experiment.

    Record years, folds, features, target, and metrics.

  2. Audit the data

    Check files, bytes, events, labels, and positive targets.

  3. Pin the fold manifest

    Bind each fold to one filename, size, SHA-256, and contract.

08 · Cost control

Calibrate before committing to a long run

A 500-step run tests the full training path and estimates one fold's cost.

500 steps

Exact optimizer-step stop reached.

17.08 minutes

1,024.878947258 seconds end to end.

4.70–5.69 hours

Projected 10,000-step Fold-2 range.

  1. Rebuild the environment

    Pin libraries, CUDA, configs, and clean upstream code.

  2. Calibrate the runtime

    Run the official entry point for 500 steps, without test or predict.

  3. Measure the whole cycle

    Include startup, data stalls, epoch boundaries, and validation.

  4. Decide whether to continue

    Use measured runtime and memory before the full fold.

Why this helps: plan hardware from evidence and catch loader problems in minutes, not hours.

10 · Test-only campaign

Evaluate all twelve released weights

Next, test every official released checkpoint under its official fold.

This is a test-only evaluation of official released weights, not twelve new training runs. Each state dictionary loaded 182 tensors with strict=True; training, validation, prediction, and automatic retry were disabled.

Scientific test wall time totalled 5749.570263385773 seconds (95.83 minutes); median fold time was 549.7098723649979 seconds. Each fold waited for the previous independent PASS.

11 · Evidence

An independent verifier should distrust the summary

An Independent verifier reconstructs the claim without trusting controller metrics.

  1. Raw evidence

    Read commands, streams, exit status, config, inventories, weights, and official output.

  2. Independent logic

    Parse metrics, check ranges, recompute timing, and verify weight identity.

  3. Atomic publication

    Bind one CSV, summary, and independent result by path and SHA-256.

  4. Verify from raw evidence

    Publish only after all twelve fold verifiers PASS and raw seals remain unchanged.

Full audit details are preserved in res18_unet_t1_reproduction.md. The public lecture intentionally teaches the reasoning rather than listing every artifact hash.

13 · Debugging

What went wrong—and why the failures were useful

A faithful reproduction is rarely one clean command. The key is to classify each failure before changing anything.

Recovery evidence: the preserved Fold 0 output was finalized offline and no scientific evaluation child was relaunched. Fold 2's legacy parser qualification was also an observer/provenance repair, not a scientific retry.
14 · Scientific interpretation

What this result proves—and what it does not

Good research claims stop exactly where the evidence stops.

What this result proves

  • All twelve pinned official checkpoints load strictly and execute under their official folds.
  • Raw metrics independently reconstruct to AP 0.45276400446891785 ± 0.08821731990844857.
  • The result is close to the paper's reported aggregate.
  • The workflow, artifacts, and publication are auditable on this host.

What this result does not prove

  • It does not show that we trained twelve equivalent checkpoints.
  • It does not prove paper-table provenance identity.
  • It does not resolve the authors' intended focal-alpha or positive-weight training setting.
  • It does not show that one threshold is calibrated equally well across folds.
Supported claim The agreement supports released-weight executable reproducibility: the official released checkpoints can be executed and independently verified under the pinned protocol.
Future question The official focal-alpha/config-code behavior remains a separate future training ablation. It was not silently changed and is not part of this baseline claim.
GPU boundary: 5,756 roughly one-Hz WDDM samples observed fold peaks of 15,525--19,976 MiB. Child attribution was unavailable and sampled maxima may miss transients; these are not absolute CUDA peaks.
15 · Reuse

A practical checklist for the next reproduction

The same discipline applies whether the next target is a larger model, another history length, or our own ablation.

Before execution

  1. Write the exact scientific contract.
  2. Pin code, data, weights, and configs by identity.
  3. Audit folds, years, labels, and positive targets.
  4. Separate allowed compatibility work from forbidden scientific edits.
  5. Estimate runtime and memory with a bounded calibration.

During execution

  1. Use one immutable launch identity.
  2. Record command, PID lineage, raw streams, exit code, config, and resource samples.
  3. Do not automatically retry.
  4. Do not start the next fold before the current verifier passes.
  5. Preserve every failure and classify its layer.

After execution

  1. Recompute metrics from raw evidence.
  2. Compare source inventories before and after.
  3. Publish outputs atomically with exact hashes.
  4. Report all folds, not the most favourable one.
  5. Write both supported and unsupported claims.
16 · Summary

A baseline is a scientific instrument, not just a number

We began with a paper claim and ended with a frozen contract, an executable official baseline, a twelve-fold distribution, independent raw-evidence verification, and explicit claim boundaries.

Measured:
AP 0.452764 ± 0.088217, close to the paper reference 0.460 ± 0.084.
Learned:
Cross-fold variability is large, and AP does not replace fixed-threshold F1, IoU, or Recall.
Enabled:
Future model changes can now be compared under a frozen, audited, official-fold protocol.

Next step: freeze this baseline as the control, then resolve the training-setting discrepancy and run one declared ablation at a time.

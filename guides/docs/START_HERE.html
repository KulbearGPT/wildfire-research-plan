欢迎加入野火预测研究项目。这一页帮助你了解项目、完成第一次实验，再接上已有研究。第一次上手只需跑通一个官方 fold，不要求重跑全部实验。

1. 先了解我们在研究什么

我们研究：当卫星输入出现预设的缺失时，如何预测下一日的活跃火点。模型输出逐像素的火点概率；标签是活跃火点代理，不是完整火场边界。现有结果主要针对受控缺失实验。

先读 研究 Roadmap 的问题定义、研究过程和实验契约，理解为什么要先审计数据、修正索引、建立基线，再比较方法。Roadmap 保留早期教学脉络；当前方法、证据与运行状态以 研究交付文档 为准。

阅读后，试着用自己的话回答：输入是什么、预测哪一天、标签代表什么，以及我们如何判断一个改动有效。

官方 Fold 2 与项目 B0 不是同一个实验。 前者使用原始四年数据的官方划分和 10,000 步预算；后者使用八年数据的固定前向时间划分、修正索引与训练统计量，预算为 3,000 步。不能直接把两者分数当作方法增益。

第一条路线不需要 clone 本项目，也不依赖老师的环境或野火检查点。完整 12-fold 是后续选做项；首次入门不要直接批量启动所有 fold。

3. 开始敲命令前准备好什么

  • 自己的集群账号、CPU/GPU account，以及站点实际可用的 GPU/partition。
  • 计算节点可读写的个人实验目录和足够存储配额。
  • 教程要求的 Python/module 环境，以及计算节点的下载渠道。
  • 一份实验笔记，用来记录配置、提交号、作业 ID 和结果路径。

具体目录、空间准备和命令都在对应教程中。账户、模块名及 GPU 名称按你的站点填写，不复制老师的个人路径或 Slurm account。

登录节点只做编辑、Git、查看轻量日志和提交/查询作业。安装、下载、数据转换、训练与模型评估通过 Slurm 执行。 sbatch 返回 job ID 只表示提交成功；还要确认作业 COMPLETED、退出码 0:0，并检查实际产物。排队时不要重复提交同一实验。

4. 怎样算完成入门

首次使用官方教程时，完成以下事项即可交给导师检查：

  • 能解释所用数据、年份划分、T=1 输入和下一日预测目标。
  • 环境与数据准备作业成功，smoke 检查通过。
  • Fold 2 正式训练完成，训练步数、日志和选定 checkpoint 可查。
  • 对 checkpoint 完成教程规定的评估，能找到 AP 等指标及其对应划分。
  • 能区分自己训练的结果、作者发布权重的结果和论文的多 fold 汇总值。

Smoke 通过只说明运行链路可用，不代表已经复现论文效果。分数不同先核对划分、数据处理、预算、checkpoint 选择和指标口径；不要为了追上某个数字反复调整测试集上的选择。

如果走项目 B0 路线，把上面的 Fold 2 换成该教程规定的 B0 训练和评价协议；不要混用两套验收口径。

5. 跑通后，怎样进入研究

先看 正向信号清单，再读 负结果与未运行档案。正向清单也收录单 seed、单指标或单场景的改善，收录不等于已经确认贡献；未运行或比较无效也不等于方法无效。

与导师选定一个方向后，按 方法复现配方 找到它的最近控制组，先复现已有比较，再讨论新改动。需要基础权重时看 基线训练与导出；涉及教师或蒸馏时看 教师生成与使用。

每次实验开始前写清：要检验什么、与谁比较、哪些条件保持相同、什么结果支持或否定判断。项目历史测试年已有评估暴露，继续设计新方法时应先与导师确定确认方案。

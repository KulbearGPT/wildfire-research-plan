Step 1 / 7 · Make a prediction

A better number. An unanswered question.

You load a trained model, change its learning-rate schedule and give it another 3,000 updates. Its score goes up.

Synthetic teaching example · AP on a 0–1 scale

A · Starting checkpoint 0.40 No additional training
C · New schedule 0.44 3,000 additional updates

Can we conclude that the new schedule helped?

Reveal the missing comparison

B · Ordinary continuation: AP 0.46. It starts from the same checkpoint and receives the same 3,000 updates, using a constant learning rate.

C beats A by 0.04, but loses to B by 0.02. The total gain over A does not show a benefit from the schedule.

These are invented scores for reasoning practice. They are not measured wildfire results.

Done when: you can name the missing comparison: an ordinary continuation with a matched starting point and budget.

The candidate improves over B3, but ordinary continuation performs better. This case does not support a positive schedule effect.

B and C both start independently from B3. Starting C from B’s final weights would give it a second training stage.

Why call B − A a “continuation recipe” effect?

The continuation includes a fresh optimizer and its specified training setup. This comparison does not isolate update count from every difference between foundation training and continuation.

Even if C beats B in one run, further matched seeds are needed to assess variability. A single synthetic case establishes no scientific result.

Done when: you can identify B − A, C − B and C − A, and explain why C must not start from B.

Step 3 / 7 · Understand the control

ERM learns from the training examples.

Empirical risk minimization means fitting predictions to the available training labels using a chosen loss. Here, it is the ordinary supervised continuation that our next method must beat.

1 · Sample a batch 2 · Predict fire probabilities 3 · Compare with labels: loss 4 · Backpropagate + update weights

The loss guides training. AP is used to evaluate predictions; a lower training loss alone does not establish better validation AP.

A different starting condition

ERM does not mean clean inputs only. The project control already uses FireDrop and BlockDrop. X22 keeps those rules; its intended change is the learning-rate schedule.

Inspect the augmentation settings

FireDrop and BlockDrop each have probability 0.3 and can overlap. Block severity is sampled at 25% or 50%. Removing these augmentations only from ERM would make the schedule comparison unfair.

B3 itself is a corrected T1 foundation trained with FireDrop and BlockDrop. It is neither clean B0 nor your official Fold 2 checkpoint.

Connect the words to a formula and one update

empirical risk = (1 / N) × sum of loss(predictionᵢ, targetᵢ) 

# Teaching pseudocode; use the existing runner for real experiments.
optimizer.zero_grad(set_to_none=True)
logits = model(augmented_inputs)
loss = supervised_loss(logits, targets)
loss.backward()
optimizer.step()

Step 4 / 7 · Find the extra changed variable

Would you trust this comparison?

For each case, choose the repair that lets us test the schedule. The goal is to change one intended factor while matching the rest.

Three short reasoning exercises

1 · ERM gets 1,000 updates. X22 gets 3,000.

Answer and explanation

Use the same 3,000-update budget and B3 starting weights. Otherwise, schedule and training budget change together. Dividing AP by the number of updates does not remove this confound.

2 · X22 starts from ERM’s final checkpoint.

Answer and explanation

Load the same actual B3 checkpoint for both runs. A matching seed or filename cannot undo the extra training already present in ERM’s final weights.

3 · X22 uses best validation AP; ERM uses final step.

Answer and explanation

Use the same final-step rule for these continuations. Different selection rules can change scores independently of the schedule. Test scores must not be used to choose checkpoints.

Done when: you can name each confound: budget, initialization history and checkpoint selection.

Step 6 / 7 · Interpret all conditions

An average can hide a trade-off.

Report each condition. Compute the missingness summary using the same predeclared rule, even when one condition gets worse.

Project evaluation conditions
Condition What the model receives
M00 · Complete Complete inputs
M01 · No fire history Active-fire history removed
M06 · 25% blocks 25% structured block missingness on dynamic inputs
M07 · 50% blocks 50% structured block missingness on dynamic inputs

Static inputs remain in the block conditions. Missingness here is controlled corruption; it does not establish natural-outage robustness.

Block = (M06 + M07) / 2

Here ERM improves Primary by 0.06 but reduces clean AP by 0.02. The continuation helped under the chosen missingness summary, with a clean-input cost.

Can we write “robustness improved everywhere”?

No. M00 regressed. State both outcomes, and keep the single-seed scope. Primary averages three separately computed AP values; it is not AP computed from pooled predictions.

An absolute AP difference of 0.01 corresponds to one point on a 0–100 presentation scale.

If ERM does not improve

Record the valid result. A negative result does not automatically mean the implementation is broken. Check the contract before interpreting it.

If the inputs or masks differ

Repair or relabel the comparison. It cannot establish either a positive or a negative effect under the intended contract.

This practical uses T1, seed 0 and 2021 validation. Historical 2022/2023 results have already been inspected; those years are not newly untouched confirmation data.

Step 7 / 7 · Make your reasoning reviewable

Submit evidence, not just a score.

Your report can be short. Another student should be able to locate the artifacts and understand exactly what you compared.

  1. The question: your pre-run prediction and an outcome that would contradict it.
  2. The comparison: B3 identity, data/statistics, seed, budget, augmentation and checkpoint rule.
  3. The evidence: code revision, configs, job IDs, completion records, checkpoints and original metrics.
  4. The result: A/B table, improvements and regressions, one supported conclusion and one limitation.
  5. The next question: how would you test the schedule while retaining a fair control?

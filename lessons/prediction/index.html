Step 2 · Keep the grid

A map needs a prediction at each location.

Trace Cedar’s input grids, prediction and target before drawing your own pipeline.

A spatial encoder extracts features. A decoder restores a spatial grid. A pixel head produces one score per output location.

Input [B, C, H, W]Spatial encoderDecoder + skip featuresFire logits [B, 1, H, W]

This is a schematic binary-map interface; intermediate resolutions depend on the implementation. A global classification score does not itself specify a fire boundary.

Try it yourself

For an input [4, 40, 32, 32], what does 40 mean?

Reason through the question and every option

How to reason: Read the declared layout before interpreting its numbers: [B, C, H, W] = [4, 40, 32, 32]. There are four samples, forty features per sample, and a 32 by 32 spatial grid.

  • Forty independent fires — not the answer. Samples belong on B, which is 4 here. Even four samples need not be four independent fires: patches or dates can come from the same event.
  • Forty processed feature channels — correct. C is 40, so each sample contains forty processed feature channels on the same grid. A channel describes a feature, not an independent event.
  • Forty days of history — not the answer. This T1 example has one observation day. A time axis must be established from the input contract; a channel count alone does not specify history length.

Take away: Annotate axis names before counting events or days. Tensor shape alone does not establish statistical independence.

For sequence inputs an explicit time axis may appear. Merely reshaping B and T together does not teach a model temporal relationships.

Done when: you can label B, C, H and W and explain the output grid.

Step 3 · Calculate

A pixel head mixes features, then produces a probability.

At one location, suppose two already extracted features are 0.8 and 0.2. A simplified 1×1 head computes z = w₁ × 0.8 + 1 × 0.2 − 0.5. Adjust w₁.

At threshold 0.5, this pixel is predicted as fire.

The same head parameters are shared across locations, but the features differ. Earlier convolutions can include neighborhood information; a 1×1 head does not imply that the model sees only one original pixel.

Done when: you can distinguish a feature, a logit and a probability.

Step 4 · Train versus display

Where does the label enter?

Legal inputs → modelLogits + target → training lossGradients → parameter update

During evaluation, logits can be mapped to probabilities and thresholded for display. The ground-truth map is used to score the prediction, not to create it.

Try it yourself

What does applying sigmoid accomplish?

Reason through the question and every option

How to reason: A logit z is an unrestricted real number. Sigmoid applies p = 1 / (1 + exp(-z)): z = 0 becomes 0.5, and larger logits produce larger outputs. This is a forward computation using the current weights.

  • It trains the model — not the answer. Training requires a loss, gradients and an optimizer update. Applying sigmoid alone changes the representation of a prediction, not the model weights.
  • It maps each real-valued logit into (0, 1) — correct. Mathematically, sigmoid maps finite logits into (0, 1). This gives a probability-shaped output that can be thresholded, but its reliability still requires evaluation.
  • It proves the probabilities are calibrated — not the answer. Being between zero and one is insufficient for calibration. For example, predictions near 0.8 should correspond to about 80% positives across an appropriate evaluation population; sigmoid does not guarantee that.

Take away: Keep activation, learning and calibration separate. A plausible probability at one pixel establishes none of the model’s overall accuracy.

One update, in pseudocode
optimizer.zero_grad(set_to_none=True)
logits = model(inputs)
loss = configured_loss(logits, target)
loss.backward()
optimizer.step()

Follow the configured loss’s input convention. Do not silently replace the official training objective with a teaching example.

Done when: you can draw separate arrows for model input, supervision and evaluation.

Step 1 · Name the methods

Specialize the training distribution.

Mixed-severity block specialist

X14: specialize on block missingness while sampling 25% or 50% severity.

Fixed-severity block specialists

X17: train separate 25% and 50% specialists.

Both belong to the block-specialist family. In the active runner, these use block dropout with probability 1 and fire-history dropout with probability 0; the mixed specialist samples severity while each fixed specialist uses its declared severity.

These names describe interventions, not guaranteed improvements.

Try it yourself

What is the closest control for the fixed-severity design?

Check your reasoning

The mixed specialist directly tests whether splitting severity into separate specialists adds value. Frozen foundation and ERM answer additional, different questions.

Done when: you can identify the specialization difference and its nearest control.

Step 2 · Route

A system may select different models for different conditions.

The retained condition-specific route uses an ordinary control for complete inputs, cosine continuation for no-fire-history inputs, and the relevant fixed-severity expert for block conditions.

Step 3 · Count the cost

Two specialists are two training runs.

For one history setting and one seed, each continuation uses 3,000 updates. Count the independent models before interpreting the system gain.

Comparison componentModelsContinuation updates
Mixed-severity specialist13,000
Two fixed-severity specialists26,000 total
ERM + cosine + two fixed experts412,000 total

These totals exclude foundation training and evaluation. They do not imply equal GPU-hours across settings or four forward passes per condition: the route selects a model, while storage and training still involve the full set.

Try it yourself

The system matches ERM on clean AP. Does that prove each expert preserves clean performance?

Check your reasoning

The system uses ERM for clean inputs. Evaluate specialists individually to learn whether they preserve clean performance.

Done when: you separate training/storage cost, routed inference cost and standalone expert behavior.

Step 4 · Design

Use both system and component comparisons.

Reuse the report review criteria; add an explicit row for each specialist and label routed system rows separately.

  1. Match foundation, seed, data, optimizer budget per run and checkpoint rules.
  2. Evaluate each specialist under all four conditions.
  3. Compare fixed experts with the mixed specialist at matching severity.
  4. Compare the composed system with fresh ERM and separately with the frozen foundation.
  5. Report extra models and total training cost alongside gains and regressions.

Active specialist and composition recipes retain exact command roles. Do not submit the entire set merely to complete this planning lesson.

The retained system’s positive evidence does not establish an independent specialization mechanism: fixed-severity attribution did not pass every required held-out comparison. Keep that limitation when discussing the route.

Step 5 · Submit

Propose one experiment you could learn from.

Write a question, its matched comparator, a result that would support it and a result that would weaken it. Include the proposed resource budget before running anything.

Read both positive signals and negative/invalid/unrun records. A descriptive name helps you remember the mechanism; it does not replace its evidence status.

You have now moved from defining a forecast to designing a defensible comparison. Keep the same discipline for the next research question.

Done when: your proposal is narrow, falsifiable, matched and costed.
